# 飞书 Base 字段映射

默认 Base：`A80Xb9jOnaexcKswFkacPBoEnAf`（`泛函｜公司&职位&候选人`）。每次运行仍先用 URL 解析与字段读取核验实时结构。

## 候选人表

候选人表：`tbldGJk6awx45Chc`。

- `姓名 & 昵称`: 候选人姓名。
- `候选人职位类目`: 与 JD `职位分类` 做集合相交的候选池门控字段。
- `实习 & 正职`: 候选人当前寻找实习、正职，或两者都可。
- `候选人检索字段 JSON.文本`: OpenAPI 可读的首选简历 JSON。
- `候选人检索 JSON（Agent回填）`: 首选字段为空时的文本 JSON 回退。
- `候选人检索字段 JSON.附件`: 两个文本字段都不可用时的 JSON 附件回退。
- `简历`: 入选候选人的原始简历附件。
- `作品集/补充材料`: 其他证据附件。

`候选人检索字段 JSON` 是 Object 字段，当前 OpenAPI 返回 unsupported；不要把读不到该列误判为没有 JSON。

## 职位表

岗位表：`tblcprcqjXs35bdq`。

- `岗位名称`: 岗位名称；用于推断实习或正职。
- `岗位描述`: 原始 JD 与要求。
- `岗位属性`: 全职、实习、线下、远程、高管等属性。
- `职位分类`: `增长/运营/市场`、`产品`、`研发`、`算法`、`设计`、`商务/销售`、`数据分析`、`首席科学家` 或 `无匹配标签`。
- `岗位状态`: 招聘生命周期。
- `群聊`: 关联公司的招聘沟通群 lookup。

简历找岗位时，读取完整JD、`岗位状态`与当前字段选项，明确暂停/结束的岗位不进入推荐；状态未知先核实，不能宣称正在招聘。继续分页直到`has_more=false`，记录读到的岗位与排除/待确认数量。

## 公司资料获取

从岗位表的实时字段定义找关联公司record或公司信息lookup，再读取该公司的业务、产品、客户类型、团队/阶段和原始资料链接。公司表ID和字段名在每次运行时解析，不预设未验证的ID。

有公司名称但没有关联字段时，先用业务、官网或统一标识核对公司身份，再查可访问公司记录或官方网页。同名、关联错误或来源矛盾时保留待确认，不合并记录，也不修改表结构凑关系。

读取数据库介绍后，按Skill的`Information Enrichment For Selected Pairs`补全当前匹配需要的信息。数据库自述与公开发现分别保留来源；历史融资/团队报道不能直接当作当前状态。
