# 招聘推荐与审核话术

依据用户提供的业务沟通指南改写。只用于匹配与审核结束后的草稿；不包含原始业务文档、候选人资料或发送动作。

## 选话术前

先看审核结论，再看受众和当前对话。只用已读到的公司业务、岗位任务、候选人贡献及确认过的条件。称呼与此前沟通一致，陌生关系用“您好”或“您”，不自动称“老师”。每段只给一个下一步。

| 情况 | 本次输出 |
|---|---|
| 高匹配，尚未表达兴趣 | 具体推荐理由，询问是否想了解该岗位；多岗位只请回复编号 |
| 高匹配，已感兴趣但未明确同意推荐简历 | 简短衔接理由，确认是否同意向这家公司、这个岗位推荐现有材料 |
| 高匹配，已有上述明确同意且未撤回 | 沿用同意，生成推荐草稿或下一步说明，不再询问同一个批准 |
| 低匹配 | 委婉说明一至两个决定性岗位差异 |
| 关键证据不足 | 最多三个具体补问，不生成推荐或拒绝 |

“这个岗位有兴趣”或“帮我找工作”不能当成对具体公司的材料分享同意。公司、岗位或材料范围超出原同意时，只确认新增范围。更晚的撤回或明确不感兴趣优先。已有材料直接使用，不要求重发。

审核高匹配与材料分享同意是两个判断。公司版可以作为内部待发送草稿；实际向公司分享身份或简历需已有适用同意及发送授权。缺少同意时把确认草稿给运营人员，不在公司群展示候选人身份或材料。

## 高匹配：给公司推荐候选人

突出“做过什么、与岗位哪项任务相关、下一步聊什么”，避免逐项复述技能表或整份简历。未外部核实的成果用“从简历看”或“简历中提到”，不称已验证。

```text
{姓名}｜{已知的相关角色/年限/地点}
从{简历/已确认的项目沟通}看，{个人承担的任务与具体成果}，与您这边{岗位核心任务}比较贴近。
建议进一步聊聊{与岗位相关的项目细节或面试重点}，看实际工作方式是否合适。
```

面试重点是对已有支持证据的深入了解；尚未解决的必须条件不能放进高匹配推荐。姓名、年限等未知就省略，不保留空占位符。原始简历在实际获授权交付时紧跟该介绍；文件或链接尚未交付时不写“附件已发”。

## 高匹配：给候选人推荐公司与岗位

先写公司具体做什么、这个人去做什么，再连到候选人经历。只说有依据的匹配点，避免“完美匹配”“肯定能过”“公司很看好您”。

```text
{岗位}｜{公司}｜{已确认的地点/办公方式；未知则省略}
他们主要做{业务/产品}，这个岗位重点负责{核心任务}。
您之前{具体经历或个人贡献}，与这里的{对应任务}比较贴近。
```

随后按已有沟通只选一个结尾：

- **还未表达兴趣**：“您对这个方向感兴趣吗？我可以继续把完整 JD 和团队信息发您。”多岗位由主匹配 Skill 合并成回复编号的结尾。
- **已感兴趣，分享同意未知**：“您愿意让我们把已有简历和相关材料推荐给{公司}的{岗位}吗？您确认后，我们再向企业推荐。”没有重复索取简历，也不把兴趣当批准。
- **已明确同意，尚未发送**：“好呀，就按您已确认的{公司}—{岗位}准备推荐。”有明确承办安排时可写“我们会按您确认的范围向企业推荐”，不能称已经发送。
- **实际已发送且可核验**：“已按您确认的范围向{公司}的{岗位}推荐。{已确认的反馈方式或下一步；没有则省略}。”只在记录支持已发送时使用。

候选人已选定岗位、用户要求完整 JD 时，交付可读取的原文或有效原始链接，并保留已知公司介绍；不再请对方重选编号。完整 JD 作为后续独立消息或材料，不挤进多岗位简版。无法读取就说明缺项，不冒充已经附上。

## 低匹配：委婉告知

只说这个组合的差异。明确不符合与尚未提供证据分开，缺证据走下一节。自己的审核不能写成企业已经拒绝，也不能判断人的整体能力。

候选人版：

```text
我仔细看了您的经历和岗位要求。这个岗位目前需要{明确必须条件}，而您已确认的{相关经历/工作意愿}与这一点有差异，这次建议先不推进这个岗位。
{仅在已有其它合适机会或明确后续安排时，补充具体下一步；否则省略}
```

公司版：

```text
这位候选人的{已确认的经历/工作意愿}与岗位要求的{决定性条件}有差异，这次建议先不推进这个人选。
{必要的简短解释；没有则省略，不披露无关个人信息}
```

不要为了委婉编造“其它方面都很优秀”，也不自动承诺持续留意、一定有其它岗位或企业会放宽要求。

## 待确认：补充材料或岗位口径

承接已收到的内容，直接说明缺哪个事实、为什么要问。优先用一个消息列最多三个短问题；已有作品里能找到答案就先读取，避免让候选人重复发材料。

候选人版：

```text
您的简历已收到。这个岗位比较看重{关键能力/条件}，想再确认{最多三个决定性问题}。
{若缺实战证据：可以补充一个相关项目中您负责的部分、实际交付结果，或尚未提供的案例链接。}
了解这些后，才能更准确地判断这个岗位是否合适。
```

公司版：

```text
JD 已收到。还想确认{最多三个缺失或冲突的关键岗位条件}，这会影响候选人的选择。
您确认这些口径后，我再据此判断这个人选是否合适。
```

仅问影响本次结论的条件，不把所有公司介绍、预算、学历、福利等变成固定问卷。未知迁移意愿、最低薪资或必须技能实战不能出现在高匹配推荐里。

## 已有反馈时的结尾

仅在当前对话确有该反馈时使用；不因为提供这些模板就自行追问、重新检索或执行流程推进。

- **明确不感兴趣且已说明原因**：“明白，{简短复述已确认的偏好}。这次先不推进这个岗位。”不要再问已经说过的原因。
- **明确不感兴趣但没有原因**：“没问题。这几个机会里，哪些地方不符合您的预期？您的反馈可以帮助下一次筛选。”已有原因就不用这句；没回复不等于拒绝。
- **低匹配但仍希望争取**：“明白您的想法。目前的差异主要是{决定性条件}，需要先确认企业是否有调整空间，才能判断是否值得继续。”保留低匹配结论，不自行承诺破格或直接投递。

## 没有可推荐结果

完整读取、审核后确实没有合适组合时，对候选人写“目前这批岗位里，暂时没有与您已确认条件合适的机会”；对公司写“这轮暂时没有符合{决定性要求}的合适人选”。没有明确共同原因就省略原因，不批量评价未入选的人。

数据库、分页或材料读取失败时，写“目前资料还未读全，暂时无法给出完整的推荐名单”，并说明实际缺项；不能写成已经查遍、没有人才或企业拒绝。没有实际跟进安排就不承诺后续自动留意和通知。
